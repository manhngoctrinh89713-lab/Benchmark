# 文件与文档管理 MCP 调研与选型

调研日期：2026-11-01。实现为统一的`tools/files/`模块，不按文件系统、网盘或文档软件拆分。优先看功能覆盖、文件环境适配成本及许可证，star仅辅助参考。

## 核对范围与复用程度

Filesystem核对`src/filesystem/index.ts`的工具定义、`lib.ts`的读写/搜索/编辑以及`path-utils.ts`和README。采用其工具粒度、批量单项错误、目录递归、访问边界、diff预览、逐步替换和CRLF处理；读取部分合并为统一的`read_document`，用格式识别加按行分页替代单列的文本与文档转换两个工具。工具语义移植为Python后端，不宣称直接提取并执行了TypeScript业务层。

编辑保留`oldText/newText`字段、顺序应用、dry_run和原换行样式，要求每项唯一精确匹配，不采用上游宽松空白匹配。glob采用Python fnmatch而非minimatch：忽略大小写，`*`可跨路径分隔符，无特殊`**`语义。写入默认不覆盖；移动和复制目标必须不存在。

MarkItDown核对`packages/markitdown-mcp/src/markitdown_mcp/__main__.py`、README及转换库依赖声明。直接提取转换器创建与转换返回，改为同步`convert_local(path)`，禁用插件，去掉远程URI与整个服务启动流程。`scripts/extract_document_converter.py`可从固定快照重新生成转换核心，改动及原始/输出hash见`local_files/EXTRACTION.json`。

实际格式解析直接复用`markitdown[docx,pdf,pptx,xlsx,xls]==0.1.9`，不是自行实现Office/PDF解析器。PyPI发行版本固定运行库，调研commit固定MCP核心来源，两者分别记录；不引入上游当前使用的MCP SDK 2.x，继续沿用项目1.x SDK。

`read_document`在MarkItDown之外补了两层本地逻辑：格式识别和文本解码。格式识别按文件头（PDF签名、ZIP内`word/document.xml`、`xl/workbook.xml`、`ppt/presentation.xml`、EPUB mimetype、OLE签名、图片签名）判断，扩展名只在无法判定时兜底，因此改名或无扩展名的文档仍可读取；文本类文件不经过转换库，直接按utf-8/gb18030/UTF-16解码，保留原始行号和字节hash。分页用行号`offset`/`limit`与`next_offset`，对应anymd的cursor思路但不绑定token预算。图片不转写：图片文件用Pillow读取格式、尺寸、模式并返回元数据，DOCX/XLSX/PPTX的`*/media/`条目只计数并在warnings说明，扫描PDF仍走空文本提示。OCR与视觉描述未引入；anymd与Docling的OCR能力只作比较。Pillow原本随`markitdown[pdf,pptx]`安装，pyproject中显式声明，不引入新的安装包。

Desktop Commander核对README的文件/搜索/终端能力；Google Drive核对README和index.ts的注册/调用。两者仅作功能比较。

## 数据、边界与验证

直接以真实文件作为状态，不将正文再保存一份JSON。初始scenario提供逻辑时钟，工作区复制到运行区；state保存逻辑时钟和事件序号。初始state含mutation_events时，成功修改后追加写入摘要和删除路径；不保留被删文件的字节副本，也没有文件历史恢复接口。文件计划执行与state保存并非跨文件原子事务，部分I/O失败可能造成文件与事件不一致，由宿主评测报错。文件锁协调本模块实例，不能约束外部编辑器。

工具路径限运行files，拒绝越界、链接/junction、硬链接和备用数据流。支持文件组织、文本编辑及文档内容读取；不提供云盘权限、共享链接、Office版式创作/编辑、终端、OCR或语音转写。

验证项目包括文档读取及分页、编码回退、编辑预览、覆盖/hash前置条件、目录复制移动删除、目录边界及schema一致性。历史版本中关于文件字节历史和故障恢复的验证说明不适用于当前实现；当前私有事件只含摘要，不能恢复文件。宿主未开放符号链接创建权限，该用例未实际执行；代码保留链接和junction拒绝逻辑。

验证脚本使用临时目录，不在正式运行环境和运行记录留下演示操作。
