# 电脑与服务器维护 MCP 调研与选型

调研日期：2026-11-01。目标是Windows个人电脑和Linux服务器两类维护流程，优先考虑应用/进程/启动项/清理，以及服务/配置/日志/磁盘/备份。star只作活跃度线索，实际以功能、源码可提取性、许可证和本地场景适配成本为准。

## 实际源码复用

提取脚本scripts/extract_upstream.py从固定源码生成local_maintenance/upstream_helpers.py，EXTRACTION.json包含符号、原始行号、输入/输出hash及变化：

| 来源符号 | 保留与调整 | 实际调用位置 |
| --- | --- | --- |
| Windows search_process_by_name | 保留名称不区分大小写子串筛选；去掉MCP装饰器、psutil枚举与宿主机异常；改名filter_windows_processes并返回匹配字典列表 | PCStore.pc_list_processes，直接决定工具返回哪些场景进程 |
| RHEL ProcessInfo | 保留原Pydantic字段模型，只提取类本身 | parse_ps_output的输出，初始化Linux进程状态 |
| RHEL parse_ps_output | 保留原解析函数，包括命令行空格处理和错误行跳过行为 | ServerStore.prepare读取scenario.process_snapshot中的ps aux文本，转换为可修改的进程状态 |
| RHEL format_bytes | 保留原纯函数 | 两侧磁盘报告的used_human显示 |

运行不导入上游服务器模块、注册表/psutil操作、命令运行器、SSH、DBus或备份远程客户端。上游原始许可证及NOTICE随共享包保留；本地应用/服务状态机、资源账本、配置校验、ZIP备份、文件事务和恢复由本项目实现。备份没有假称直接复用restic引擎；配置校验也没有假称执行nginx -t等原生程序。

## 工具组合

PC侧22个：系统概况、应用目录/安装更新卸载/启动、进程列表/详情/挂起恢复终止、启动项列表/启停、磁盘/目录分析、缓存列表/清理、个人文件列表/读取/哈希写入/删除，以及备份创建/列表/校验/恢复/删除。完整[工具清单](../../../prompt/tools/pc.md)。

Linux侧20个：系统概况、服务列表/详情/控制、配置读取/按哈希保存/声明规则校验、进程列表/详情/信号、日志过滤/裁剪、磁盘/目录分析/文件读取，以及备份五个工具。完整[工具清单](../../../prompt/tools/server.md)。

没有把自由命令执行器作为工具集合核心。文件路径按模型平台解析，操作对象限制到登记应用、缓存、服务和备份根；这样能用真实文件和状态关系检查结果，同时维持本项目既有的可重置初始模板、独立运行目录和事件记录规范。

## 已验证行为

verify_local_maintenance.py实际调用两侧全部42个FastMCP工具并比对schema。覆盖应用体积变化、运行应用修改拒绝、启动项状态、缓存锁定文件跳过、按年龄清理、个人文件哈希更新及删除、真实ZIP清单与二进制原字节恢复、恢复覆盖/损坏拒绝、配置暂存与重载/重启不同失败结果、依赖缺失、主进程终止/服务失败/日志关联、日志过滤和裁剪后的精确磁盘变化。

还验证严格布尔/整数参数、路径/保护/哈希边界、最后写入冲突、同键并发创建只生成一个备份、发布中断后恢复计算结果及重放、平台隔离、模拟磁盘不足整体回滚、模板变更检测，以及初始模板原字节不变。测试使用临时目录，不创建正式运行。

补充检查覆盖紧凑JSONL及缺失末尾换行的追加/裁剪、其他服务日志原字节保持、内存不足回滚，以及恢复计划后段遇到受保护配置时整体不提交。共享、PC和服务器三个wheel构建成功，verify_wheels.py核对源码/提取hash、42个schema与工具文档、七份许可证/NOTICE，并执行打包版备份恢复与配置重载；九套现有MCP可同进程加载，依赖检查通过。
