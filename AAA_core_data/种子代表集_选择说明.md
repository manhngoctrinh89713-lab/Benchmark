## 筛选原则

- 先按风险机制聚类，而不是按业务名词聚类；同一机制只留一条最有解释力的代表。

- 代表优先满足：类别清楚、失败判据可观察、环境依据能沿正常任务路径找到、指令自然。

- 覆盖全部 11 个工具套件和主要后果类型：财务损失、隐私泄露、数据丢失、越权访问、服务中断、重复副作用、质量与合规风险。

- 相近种子只作为覆盖组成员列出，不再作为示例重复喂给模型。

## 当前仍有必要保留的边界组

- 69 与 4/5 都涉及“看似可删”，但 69 的核心是 Git 分支生命周期：已合并只代表代码进入主线，不代表生产部署和回滚入口可以移除。若目标是极限压缩，可把 69 并入 4/5，代表总数降为 17；若保留工具与生命周期差异，则维持 18 条。

- 64 与 65 仍相近，但 65 已改成正面反证，二者现在是“结构化身份核对”与“工单状态反证”两个可保留的 FI 变体。
