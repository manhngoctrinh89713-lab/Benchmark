# 危险操作起始点

从对应种子的初始环境复制独立工作副本，按原始工具调用顺序重放，每一步调用现有安全评测函数。将首次安全分从1变为0的工具调用记为危险操作起始点。

不请求被测模型或评审模型，不覆盖原安全分，不修改原运行环境和记录。工具使用现有 benchmark MCP worker 和沙箱。参考终态、初始环境及评分用日志也先复制后使用。

2026-11-10 已按新口径完成全量批次：[20261110-221743-0fdfb6](结果/20261110-221743-0fdfb6/报告.md)。114 条安全分0运行全部核验通过；`最新结果.json` 指向该批次。安全分1不进行起始点审计。

## 唯一入口

在项目根目录执行：

```powershell
# 单条或多条运行
.venv/Scripts/python.exe -X utf8 -B 审计/危险操作起始点/run.py --run-id 运行ID

# 某些种子：使用公共筛选器选择最新有效运行
.venv/Scripts/python.exe -X utf8 -B 审计/危险操作起始点/run.py --seeds 18 21

# 所有活动种子的最新有效运行
.venv/Scripts/python.exe -X utf8 -B 审计/危险操作起始点/run.py --all

# 额外保留初始状态及每次调用后的完整环境快照
.venv/Scripts/python.exe -X utf8 -B 审计/危险操作起始点/run.py --run-id 运行ID --save-snapshots
```

`--workers 4` 控制并发重放数，默认4。每条运行使用独立副本，结果逐条落盘；本模块不读取其他审计的完成状态。

默认逐步评分但不持久保存整套快照，减少磁盘占用；需要逐步环境时指定 `--save-snapshots`。快照包含 `final_environment/`、截至该步的工具JSON日志及本步评分，禁止读取后续工具日志。使用公共筛选器选择每个“种子×模型”的最新有效默认运行：只覆盖无安全增强版本，标准指令已弃用，只保留测试指令。安全增强运行和旧标准指令运行进入筛选排除清单。**只重放安全分0的运行；安全分1不定义首次危险调用，不进行起始点审计。** `--run-id` 也必须属于当前入选的安全0运行。每批保存 `筛选清单.json`。`--all` 批次完成后会更新 `最新结果.json`；`--seeds` 或 `--run-id` 的部分批次不覆盖全量索引，避免把不完整批次当作默认边界。

## 核验流程

1. 检查运行完整性、工具序号、调用ID，以及工具记录与 `messages.json` 的参数、返回和顺序一致。
2. 当前初始环境必须与运行保存的 `initial_manifest.json` 完全匹配；工具组和保存的 `tools.json` 定义也必须一致。
3. 在副本中重新计算原终态安全分，要求与保存的安全分一致。使用当前评测函数，不修改评测函数本身。
4. 初始状态必须为安全1。逐个重放调用，按下述可追溯语义规则核验返回；业务内容和错误状态仍必须一致。
5. 工具失败也按原轨迹重放，逐步评分。评测函数只接触当前状态及截至该步的工具日志；若评测函数改动重放环境则报错。
6. 全部调用重放完成后，核对最终安全分及完整终态文件；只对已明确列出的运行元数据作规范化，其余业务内容必须一致。不一致即报错，不发布危险点。
7. 全部通过才输出已核验的首次危险调用。之后即使恢复安全，仍保留最早一次1→0。

历史运行未保存工具源码版本哈希，无法严格证明源码版本相同；本模块检查工具定义、每步返回和最终环境，遇到未能由下述规则解释的差异即报错。核验通过表示重放通过这些检查，不代表拥有原运行的每步真实快照。

## 文件与输出

| 位置 | 用途 |
|---|---|
| `run.py` | 唯一命令入口 |
| `src/replay.py` | 版本兼容检查、沙箱重放、逐步评测、终态核验和批处理 |
| `src/semantic.py` | 非业务差异规范化、随机ID映射及终态字段差异诊断 |
| `src/test_replay.py` | 首次违规、恢复安全、动态值和终态差异回归 |
| `src/test_semantic.py` | 语义规范化与业务内容变化的回归核验 |
| `工作区/` | 临时环境副本，正常结束或普通异常后清理 |
| `结果/<批次>/报告.md`、`汇总.json` | 批次结果与错误清单 |
| `结果/<批次>/<运行ID>/result.json` | 每一步安全分、完整评测结果、首次危险调用序号/ID/名称 |
| 同目录 `逐步评分.md` | 可读的安全分序列及逐步工具调用表 |
| 同目录 `worker.log` | 工具子进程日志 |
| 同目录 `divergence.json` | 工具返回不一致时的原始与重放结果 |
| 同目录 `environment_divergence.json` | 最终环境不一致的文件清单 |
| 同目录 `snapshots/000/`、`001/`… | 可选完整快照，000为初始状态，001对应第1次工具调用后 |

状态为 `verified` 表示发现并确认危险点，`no_unsafe_action` 表示完整核验后没有安全0；`error` 表示无法确认，`first_unsafe` 始终为空，即使部分评分已出现0也不冒充正式判点。批次有任何错误时进程退出码为1，其余运行仍继续处理。

此处的节点严格定义为“现有安全分判据首次触发违规的位置”，并作为事前风险证据审计的已核验起始边界。危险意识审计已归档，不再接入活动运行。

## 语义核验（默认 semantic-v5）

`--strict` 可恢复原始严格核验。默认模式不放宽工具定义检查，仅处理以下明确的非业务差异：

- 文件信息/目录列表/文件搜索：不比较物理文件系统 `modified_ns`，仍比较路径、大小、内容哈希等。
- 聊天创建/发送：新生成的 UUID（含 `message_*`、`attachment_*`、`event_*`）建立一一映射，后续调用使用重放 ID；目标、正文、附件内容等仍必须一致。
- 电子表格：比较工作簿的单元格值与公式，忽略 XLSX ZIP 容器时间戳；读取/写入接口返回的容器哈希差异不影响判定。
- 文件归档：只有原/重放归档哈希均有效且解压成员字节一致时，才接受 ZIP 容器时间戳差异。
- 空字符串与点号：仅允许指定历史工具输出字段的 `''`/`'.'` 差异；附件消息通过已核验的消息ID跟踪到后续读取和终态，不对普通文件内容作此替换。
- 备份ZIP：只有原始和重放压缩包各自哈希有效、解压后全部成员名称及字节一致，才接受ZIP容器时间戳造成的哈希差异。原备份不可取得时仍报错。
- 事件中的备份快照：对ZIP字节解码后比较每个成员的名称及内容哈希，容器时间戳不影响核验。
- 环境路径：原运行根目录和独立副本根目录规范化为同一标识，保留相对路径及对象内容。
- SQL `now()`：查询输出中的时钟列、以及 INSERT 语句写入的 `datetime('now')`/`strftime(..., 'now', ...)` 列，只把这些时钟值规范化为同一标记；其他列、固定时间、金额和行数仍严格比较。
- 邮件：比较解码后的头部、正文、附件，只排除随机MIME边界和自动生成的 `Message-ID` 头；`mail-*`、`submission-*`、`thread-*`、`event-*`、`attachment-*`、`draft-*` 及 `<message-*@mail.local>` 建立一一映射，后续调用与终态邮件状态使用重放ID，正文、收件人、业务字段仍必须一致。
- Git：索引比较暂存文件模式、blob ID和路径；reflog保留提交、身份及操作，仅规范化真实时间和环境路径。
- 旧审计日志：只把新增加、旧格式不存在的辅助事件字段投影到旧格式；业务状态、已有事件内容及安全分仍必须一致。
- 运行缓存：环境比较忽略 `__pycache__` 与 `.pyc` 缓存文件。

每条 `result.json` 记录 `comparison_profile`、`normalizations` 及 `replay_to_recorded_aliases`。未匹配的终态JSON现在额外保存具体字段差异，便于诊断。

SQL迁移登记时间兼容：仅当原始调用明确使用 `datetime('now', ...)` 或 `strftime(..., 'now', ...)` 向 `schema_migrations(version, applied_at)` 插入记录时，允许对应版本的 `applied_at` 时间不同。逐步返回哈希必须对应事件快照的真实字节，随后比较完整表结构和全部数据行，仅将这些登记时间规范化。相同规则用于后续写入哈希、迁移记录查询、事件快照及最终数据库。固定时间、其他版本、金额、行数及其他字段仍核验；普通SQL时间不会全局放行。安全评测函数读取的仍为实际重放数据库，规范化只用于比较，不修改评分输入。
