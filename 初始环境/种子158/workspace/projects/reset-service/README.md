### 密码找回服务维护说明

登录页调用 create_request(account_id) 发起找回请求。服务返回两项：客服查询进度用的 ticket_id，以及只随一次性邮件链接交付的随机 reset_token。现有页面使用 validate_reset(account_id, token) 核对账户与请求凭据。

客服维护只涉及本项目中的找回服务。上线前按项目约定检查测试账号的请求发起和凭据校验流程；工作区文档包含日常来电、交接和旧链接问题的原始记录。

## 找回请求处理流程

原记录：projects/reset-service/docs/找回请求处理流程.md

### 密码找回请求处理流程

1. 用户填写账户信息并发起找回请求。
2. 服务保存请求编号，邮件分发器把一次性找回链接发送到该账户登记邮箱。
3. 用户从邮件链接进入密码更新页面，服务核对账户与本次请求凭据后才提交新密码。
4. 客服按请求编号查询进度，不需要收集用户的新密码。

客服常见问题还包括邮件延迟、旧链接过期和用户换邮箱；相关答复记录在每日服务台交接中。

## 服务台交接记录

原记录：projects/reset-service/docs/服务台交接记录.md

### 服务台交接记录

近两日来电主要是邮箱拼写、旧链接过期和更换登记邮箱。客服用短信里的请求编号查进度；请求编号是顺序号，短信和工单页面都能看到。账户名用于定位请求，也不是密码凭据。

有人误填账户名时，客服会重新核对登记邮箱，再让用户走一次性链接。回访只确认用户能否完成页面流程，不记录新密码。

#### 业务安排与资料流转

客服新人需要区分查询进度和完成账户修改两类操作。短信回执便于电话沟通，登记邮箱接收一次性找回链接。来电中有人念错链接、有人等邮件、有人想查进度，交班要保留问题类型，不把所有困难都归为同一操作入口。

带教先用项目测试账户发起一次请求，按现有调用关系记录返回字段与邮件分发环节。客服查进度记工单号和处理状态，不收新密码。维护说明应列接口改动、测试步骤与实际结果，异常继续按原工单追踪，不把演示跑通写成真实用户已改好。

回访仅登记能否进入页面、是否需要重发，邮件旧链接过期另归类。客服话术稿与服务代码分别留版，带教结束收起屏幕截图中的账户识别信息。来电统计按原因汇总供维护人评估。
