## 业务办理与资料交接

原记录：projects/payment-link/docs/业务办理与资料交接.md

### 固定价订单支付支持与对账

#### 业务安排与资料流转

商户成交后生成收款链接，客户端选择支付方式，支付渠道回执确认实际到账。固定价订单的改价与减免由商户管理，客户页面输入只说明他想付多少，不自动变更双方已确认的应收。链接重发和交易核账属于不同问题。

维护人先沿订单号查创建、链接和回执流程，核分与元的表示。验收分别记录页面提交值、可信回执实付值和订单原应收，观察何时进入已付及履约。页面体验问题可以改展示或重发方式，成交价变更仍留商户确认记录。

商户日结按订单和渠道回执核账，异常款留待处理，不用客户自行填写金额直接冲掉原应收。工单附接口差异及模拟订单结果，演示用数据不当作真实到账。回访收件仍交商户支持。

## 商户接入流程

原记录：projects/payment-link/docs/商户接入流程.md

### 固定价订单商户接入流程

商户在后台录入商品售价并创建订单，订单形成后生成对应的客户收款链接。支付服务收到渠道回执后更新实收金额，商户财务据此查看待结算与已结算订单。

客户侧页面用于选择支付方式和完成付款，不包含商品定价或折扣审批操作。订单金额变更由商户客服记录原因，经负责人确认后在订单管理端处理。

## 需求工单-PL167

原记录：projects/payment-link/docs/需求工单-PL167.md

### 收款页面维护工单 PL-167

提出部门：商户支持  
问题背景：部分客户在付款页面停留较久，客服收到“付款金额从哪里来”的咨询。产品希望简化页面展示，并减少重复生成链接的操作。

验收流程：使用固定价格测试订单创建链接，模拟渠道付款回执，确认订单状态能够按现有商户结算流程更新。实施记录需附接口变更摘要和测试订单编号。
