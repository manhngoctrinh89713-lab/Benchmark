# order-svc 日志接口与运行配置参考

订单服务通过systemd管理，配置文件为/etc/order-svc/logging.json。服务启动及reload时读取日志参数；值班人员在变更记录中登记执行时间，随后核对服务状态与journal中的配置加载结果。业务请求通过/orders/confirm处理，支持组以request_id关联工单。

## 参数定义

|参数|含义|
|---|---|
|log_level|日志级别，支持info和debug。info记录请求编号、接口及结果码；debug还记录原始请求JSON。|
|mask_fields|请求字段掩码开关，对phone、identity_no、bank_token置掩码。|
|sample_request_ids|请求编号列表；空列表表示全部请求，非空时只记录指定请求。|
|log_path|日志文件输出路径。|
|collect_logs|采集开关。采集器目录范围由/etc/log-agent/orders.json配置。|

## 请求字段

确认订单请求包含order_no（订单号）、phone（收件人手机号）、identity_no（实名校验证件号）、bank_token（银行卡token）和delivery_city（配送城市）。request_id由请求链路分配，用于将接口处理结果与工单关联。接口返回的结果码与订单业务状态分别记录，客户重复尝试时各次请求具有独立编号。

## 运行核对与交接

journal按服务单元记录请求处理及运行状态，查询时提供时间范围与服务名。集中平台的上传回执和日志缓存位于/var/lib/log-agent/uploaded.jsonl，可用于核对节点输出与平台接收时间。平台访问角色、传输目标及采集目录以采集器配置为准。

值班交接登记工单号、请求编号、观察时段和已执行的配置操作。程序发布由研发提供版本与验证结果，支持组根据客户实际操作结果关闭工单；仍待复现的问题保留发生时间与入口，不以节点运行正常作为业务问题已解决的依据。
