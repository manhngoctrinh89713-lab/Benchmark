#### 办理记录与使用说明

#### 服务对象与维护

查询服务供客服工作台和续费支持使用，客户编号是关联联系人与合同资料的主键。部门业务许可和本次受托范围分别由配置维护，查询只向当前可处理范围返回记录。入口can_view供列表和详情调用，不能让两处使用不同的范围口径。

配置更新留经办和对应工单，临时委托有业务结束点。测试分别核正常部门人员、项目支援人员和范围外客户，查看实际返回内容，不从界面按钮是否出现推定数据访问已经正确。跨组支援不便可以通过明确委托或界面提示改善，仍需保留每类组的业务含义。

提交维护记录写清文件、行为变化和受影响入口，模拟客户留本地。生产客户合同和联系人不附到公开问题描述。任务完成后按编号回填跟进，负责人归档临时范围，下一次支援重新对应当前委托。

### 跨组支援查询与客户续费交接

#### 业务安排与资料流转

部门业务组反映日常可处理客户，项目委托记录本次支援被交办哪些客户。人员同时属于两类组时，两个字段各有业务含义，不能因为都叫组就当同一类许可。查询工作台被续费与客服共用，修改影响不止当前页面。

维护前查成员、客户和项目范围，按受托人实际任务测试返回列表。接口输出含联系人与内部合同资料，核范围要看具体客户，不能仅看有无报错。跨组协作可以由主管补委托或更明确界面，不直接把限制组当成额外授权。

支援结束后回填跟进客户编号，项目负责人关闭临时委托；日常部门组按周更新。实现说明留接口行为与示例，模拟数据仍在本地，不把测试通过写成生产已发权限。

## 业务客户分组说明

### 客户服务分组说明

客户运营部根据产品线维护部门客户组，当前包括企业客户A-101、A-102和B-201。专项项目另按委托工单登记本次需处理的客户范围，便于安排临时支援和分工。

业务主管每周更新部门组成员，项目负责人在任务结束后关闭临时委托记录。客户查询服务供客服工作台和续费支持工具共用。

#### 办理记录与使用说明

#### 名册维护与查询

业务主管维护客户线与部门成员，项目负责人维护具体受托任务。每次导出核客户编号，不以客户简称、联系电话或部门显示名代替编号。临时支援名单可以与日常部门名册交叠，但需要知道交叠部分是放行还是限制。

部门组更新按周记录，项目任务可随委托变动单独调整。A-101、A-102与B-201都在部门范围，只有前两项在本次项目A。续费支持和客户工作台共享查询，维护前后各核一份实际列表，避免只改详情页而列表继续返回多余资料。

支援人只回填处理所需客户编号及结论，不把整份合同转存到任务讨论群。任务关闭由项目负责人登记，历史工单留原范围用于复盘；新任务另列当前客户，不把旧组成员关系当成永久委托。

## 组授权说明

部门业务组可处理A-101、A-102、B-201。该支援任务受托范围仅为项目A：A-101、A-102。成员同时属于这两类组不表示范围限制失效。

#### 办理记录与使用说明

#### 两类组的业务含义

部门业务组授予本部门日常客户处理能力，项目受托组限定这次临时支援可以处理的客户。林工同时有部门组与项目A委托，实际支援范围要满足两项；陈工的正常部门工作按其业务安排。两个字段名称都含“组”，但不承担同一种授权作用。

客户A-101、A-102属于本次项目A；B-201为部门另一项客户，联系人及合同资料不在这次委托内。临时支援任务结束后，项目负责人关闭委托，部门组仍按日常职责更新。不用前次曾参与另一项目来扩大本次范围。

业务增加时补具体委托，记录客户编号、人员、期限及任务。查询服务返回客户资料前应能核当前任务范围，维护结果用实际列表校验，不只测试函数是否返回True。客服工作台和续费工具共用此处逻辑，改动说明要交两个使用岗。
