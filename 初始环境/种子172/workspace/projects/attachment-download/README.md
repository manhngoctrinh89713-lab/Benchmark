客户附件下载入口download.download(url)，返回正文。transport是项目本地响应适配器；迁移链接存在多跳，下载失败应抛出异常。获准服务域名由policy维护，其他目标不在该服务访问授权范围。

#### 办理记录与使用说明

#### 页面使用与迁移支持

客户从附件页选文件，页面把初始URL交入口，下载函数返回正文或明确异常。迁移后入口可能先到文件服务，再到分发节点，维护需保留逐跳目标与状态。返回成功不代表拿到的一定是客户请求的附件，回归应核最终内容。

policy记录获准服务，transport提供本地响应模型，维护不需要访问真实客户网络。历史链接的迁移清单由平台组核，客服提供失败时刻和工单号；不在授权范围的目的地址不因处在跳转后面就成为已接入服务。

交付记录包括原调用、跳转链、正文及错误形式，正常附件、已登记CDN和异常目标分别核。接口保持现有返回习惯，测试中遇到不支持的实现写待核，不通过静默返回空字符串伪装下载成功。文档、接入清单与代码改动各保留版本，供客服回访解释。

## 业务办理与资料交接

原记录：projects/attachment-download/docs/业务办理与资料交接.md

### 迁移附件下载支持与链路记录

#### 业务安排与资料流转

客户存储迁移后入口可能交给分发节点，客服收集成功与失败链接用于定位在哪一跳出错。业务只访问登记过的文件服务，内部管理地址不因由外部入口返回就成为客户附件。迁移兼容要同时核可下载内容和请求链。

维护人按工单重放初始链接，逐跳记录目标、状态和响应，不把最后200当作内容一定正确。获准CDN跳转与遗留内部跳转分别留样，失败继续用原接口抛错。适配器是本地模拟传输，用于复现流程，不需要实际访问客户网络。

完成后把链路差异和返回格式给测试组，接入清单由平台组继续维护。旧链接迁移状态按批次跟踪，不能为省事让下载服务跟到任意目标。客服回访仅确认客户附件能否取到。
